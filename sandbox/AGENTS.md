# Sandbox rules

- The `sandbox/` engine (core, workspace, filesystem, editor, terminal, dependencies, processes, bridge, storage, security, project, types, utils) is plain TypeScript with no UI; `sandbox/.local/` is the project root itself and `sandbox/.output/` holds build output; execution capabilities throw NotImplementedError until a later phase, so nothing pretends to run.
- Preview renders only the last successful /sandbox/.output generation; failed generations never replace it.
- The agent's internal tools live in `sandbox/intelligence/` (search, deps, validate, errors, changes, tools); every agent file action goes through `AgentTools` so edits are boundary-checked, tracked and syntax-validated, and builds are transactional (validate → stage → verify → swap .output).
- In the app, the browser Sandbox is only a cache/preview mirror of the server codebase (`src/lib/workspace/server-sync.ts`): it loads from and sends edits to the server, and device-only files are uploaded once then dropped.
- React + Vite projects are checked before success with a TSX syntax pass (sucrase → acorn) and resolution of every relative import (`validateViteImports`), so the agent never reports a build the real Vite build would reject.
- The browser Sandbox is a temporary workspace: device storage keeps only UI state and checkpoints, never project files, buffers or .output; closing a project clears it from memory and reopening rebuilds it from the server codebase.
- Targeted edits go through `sandbox/editor/target.ts` (line range + expect, exact text, symbol, JSX element, CSS selector/media; contains/occurrence for duplicates; before/after/append for chunked growth); ambiguous, stale or partial-word targets are refused, and `update_file` rejects edits that add syntax errors.
- Module-init ordering bugs (top-level const/let/class read before declaration) are flagged as USE_BEFORE_INIT and repaired deterministically by `fixUseBeforeInit` via `ToolSession.autoFix` before each check, because AI models cannot reliably move code blocks.
- Style wiring is verified at three levels — static (`validateViteStyles`: unimported CSS, no stylesheet, unstyled classes per project and per component, unrendered components, Tailwind config), build (CSS assets in dist), and browser (`styleVerdict`); deterministic slips (invisible characters, unclosed JSX `{…map()}`, unlinked stylesheets, favicon links to missing files) are repaired via `ToolSession.autoFix` before each check, because AI repairs of these loop.

- First-pass generation: the approved plan is completed deterministically (sandbox/intelligence/scaffold.ts), fresh React stack config is written before the first AI round, and project checks are deferred while planned files are missing; this keeps repairs for real errors instead of unfinished work.
